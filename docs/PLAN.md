# BeautyBook — תוכנית בנייה

פלטפורמה מרובת עסקים (Multi-tenant) לקוסמטיקאיות: כל בעלת עסק נרשמת, מגדירה שירותים, מחירים וזמינות, ומקבלת דף נחיתה אישי עם קישור לשיתוף. לקוחות נכנסות כאורחות, מזינות שם וטלפון, רואות שעות פנויות וקובעות או מבקשות תור. לבעלת העסק יש יומן פרטי לניהול לוח הזמנים, אישור/דחיית בקשות, קביעת תורים ידנית, ניהול לקוחות ושליחת הזמנות.

## החלטות ברירת מחדל

| נושא | ברירת מחדל | למה |
|---|---|---|
| שפה וכיוון | עברית, RTL, Mobile-first | קהל היעד בישראל, רוב השימוש מהטלפון |
| Stack | Next.js 15 (App Router) + React 19 + TypeScript + Prisma 5 + PostgreSQL 16 + Tailwind | אותו stack כמו BarberManager, מוכר ונתמך היטב ב-Vercel |
| התחברות בעלת עסק | אימייל + סיסמה, סיסמה מוצפנת ב-argon2, סשן בעוגייה חתומה (iron-session) | פשוט, ללא תלות בספק חיצוני |
| הזמנת לקוחה | אורחת, ללא חשבון: שם + טלפון (חובה) + הערה | בעלת העסק צריכה דרך ליצור קשר |
| אישור תורים | לבחירת בעלת העסק: אישור אוטומטי או "בקשה" שממתינה לאישור (ברירת מחדל: בקשה) | מתאים לעבודה של קוסמטיקאית עצמאית |
| שליחת הזמנות | קישור הזמנה אישי (עם שם הלקוחה ושירות מוצע) שנשלח בוואטסאפ / SMS / העתקה | עובד מיד בלי ספק SMS בתשלום; ספק הודעות בשלב מאוחר |
| מניעת כפל הזמנות | אילוץ Exclusion ב-Postgres (`btree_gist`) על טווח הזמן של תורים פעילים בכל עסק | נכון גם בעומס, בלי Redis |
| אזור זמן | `Asia/Jerusalem` לכל עסק (שדה בעסק) | חישוב שעות נכון כולל שעון קיץ |
| כסף | מחירים נשמרים באגורות (Int) | בלי שגיאות עיגול |

## ארכיטקטורה

```
Browser (מובייל/דסקטופ, RTL)
   │
Next.js 15 App Router
   ├── /                     דף שיווקי + הרשמה
   ├── /signup, /login       בעלת עסק
   ├── /onboarding           אשף: פרטי עסק + כתובת, שירותים, שעות
   ├── /dashboard/*          אזור פרטי (מוגן בסשן)
   └── /b/[slug]             דף נחיתה ציבורי + הזמנת תור
        └── /b/[slug]/a/[token]   צפייה/ביטול תור ע"י הלקוחה
   │
Server Actions + Route Handlers
   ├── requireOwner() → businessId מהסשן; כל שאילתה מסוננת לפי businessId
   └── lib/slots: חישוב שעות פנויות (שעות עבודה − חופשות − תורים קיימים)
   │
Prisma → PostgreSQL 16
```

**בידוד בין עסקים:** ה-businessId מגיע רק מהסשן בצד השרת, אף פעם לא מהדפדפן. כל פונקציית גישה לנתונים מקבלת businessId ומסננת לפיו (גם בעדכון ומחיקה: `where: { id, businessId }`). בדיקות אוטומטיות מוודאות שעסק אחד לא יכול לקרוא או לשנות נתונים של עסק אחר.

## מודל נתונים

- **User** — בעלת עסק: email (ייחודי), passwordHash, name
- **Business** — slug (ייחודי, לכתובת הדף), name, about, phone, address, instagram, timezone, bookingMode (`AUTO` / `APPROVAL`), slotStepMin, minNoticeMin, maxAdvanceDays, bufferMin, accentColor
- **Service** — name, description, durationMin, priceAgorot, active, sortOrder
- **WorkingHours** — weekday (0–6), startMin, endMin (כמה טווחים ביום מותרים, למשל הפסקת צהריים)
- **TimeOff** — startsAt, endsAt, reason (חופשה / חסימה ביומן)
- **Client** — name, phone (ייחודי בתוך העסק), email, notes
- **Appointment** — client, service, startsAt, endsAt, status (`PENDING` / `CONFIRMED` / `REJECTED` / `CANCELLED` / `COMPLETED` / `NO_SHOW`), source (`ONLINE` / `MANUAL` / `INVITE`), serviceName + priceAgorot (צילום מצב), note, manageToken
- **Invitation** — token, clientName, clientPhone, serviceId (אופציונלי), message, expiresAt, usedAt

## מסכים

**ציבורי**
1. דף בית שיווקי — מה זה, הרשמה
2. דף העסק `/b/[slug]` — שם, תיאור, שירותים ומחירים → בחירת שירות → בחירת יום → שעות פנויות → שם + טלפון → אישור
3. דף התור של הלקוחה — סטטוס, הוספה ליומן, ביטול

**בעלת העסק**
1. הרשמה / התחברות
2. אשף הקמה: שם העסק וכתובת הדף, שירותים ראשונים, שעות עבודה
3. יומן — תצוגת יום (מובייל) ושבוע (דסקטופ), בקשות ממתינות עם אישור/דחייה, לחיצה על משבצת ריקה ליצירת תור ידני
4. שירותים ומחירים
5. זמינות — שעות שבועיות + חופשות/חסימות
6. לקוחות — רשימה, חיפוש, כרטיס לקוחה עם היסטוריית תורים
7. הזמנות — יצירת קישור אישי ושליחה בוואטסאפ/SMS
8. הגדרות — פרטי עסק, מצב אישור, מרווחים, קישור הדף לשיתוף

## אבני דרך

1. **תשתית** — פרויקט, סכמת DB + מיגרציות, התחברות והרשמה, בידוד עסקים
2. **הקמת עסק** — אשף, שירותים, שעות עבודה, חופשות, הגדרות
3. **דף הזמנה ציבורי** — חישוב שעות פנויות, הזמנה כאורחת, דף ניהול תור ללקוחה
4. **יומן** — תצוגת יום/שבוע, אישור/דחייה, תור ידני, שינוי סטטוס
5. **לקוחות והזמנות** — ניהול לקוחות, קישורי הזמנה ושליחה
6. **הקשחה** — בדיקות (slots, בידוד עסקים, כפל הזמנות), rate limit להזמנות ציבוריות, seed לדמו, הוראות פריסה (Vercel + Neon/Supabase)

**שלב הבא (אחרי MVP):** תזכורות SMS/וואטסאפ אוטומטיות, תשלום מקדמה, מנויים לפלטפורמה, כמה עובדות בעסק, סנכרון ל-Google Calendar.
